# ANCHOR backend input/output contract

## Model selection and artifact

Use the preserved v2 model only as a **research-only stored-label score**.
V3 is experimental and has no serialized model or supported inference
contract. Load the artifact at
`research/models/anchor_lapse_model_v2.joblib`; its SHA-256 is recorded in
`MODEL_ARTIFACT_REFERENCE.json`. Do not copy, retrain, calibrate, or replace it
without a separate reviewed change.

The callable strict entrypoint is
`research.anchor_handover.inference.load_model` followed by
`research.anchor_handover.inference.predict_one`. The checked-in schema is
`feature_schema.json`; the corresponding legacy research implementation is
`research/anchor_v2/inference.py`.

is required. Input key ordering is irrelevant; inference constructs the model
frame in the exact schema order. Omitted keys and additional keys (including
wearable fields) are rejected.

### Null, type, and encoding rules

- Each field may be explicitly `null`; all 22 keys must still be present.
- Numeric nulls are median-imputed by the saved model pipeline. Categorical
  nulls use the pipeline's constant-imputation path. These are technical
  fallbacks, not evidence that missing source data is clinically acceptable;
  preserve missingness and do not replace nulls with zero.
- Numeric fields must be JSON numbers and finite. Booleans, numeric strings,
  NaN, positive infinity, and negative infinity are rejected.
- Categorical fields must be strings from the enumerated fitted vocabulary.
  Unknown values are rejected rather than silently encoded as all-zero
  categories.
- Preserve the exact case and strings in `feature_schema.json`; do not
  re-encode or ordinal-map categories.
- Do not add simulated wearable, heart-rate, mood, sleep, or other values.
  Unknown/extra inputs are rejected.

### History and prediction-time data

The eight `p12`–`p168` historical count/change fields and four EMA response
fields are part of the required schema; they are not generated by the model.
The backend/data pipeline must supply them from verified source records that
were available at the intended prediction time. The exact aggregation
definitions, time units, lag origin, and minimum historical coverage have not
been verified. In particular, do not infer that a `p168` feature is supported
by 72 hours of history. A payload containing only mood, sleep, or heart rate
cannot satisfy this model contract. Until the source calculations and their
past-only availability are documented and validated, do not expose this score
as a prospective prediction.

## Output

`predict_one` returns a JSON-serializable object:

```json
{
  "model_version": "2.0.0",
  "target_status": "NOT_VERIFIED",
  "probability": 0.0,
  "decision_threshold": null,
  "decision": null,
  "explanation": {
    "scope": "global",
    "method": "tree impurity importance",
    "top_inputs": [],
    "note": "Associations are not causal explanations; the target is unverified."
  }
}
```

`probability` is the model's uncalibrated score against the supplied stored
label definition; it is **not** a verified probability of future lapse.
`top_inputs` contains global model importance, not per-request contribution or
causal explanation. `decision_threshold` and `decision` are always null.
Backend/application code must not infer alert tiers, trigger interventions, or
activate an exploratory threshold.

## Reproduction and compatibility

Tested runtime: CPython 3.10.19. Install the exact tested dependencies from
`requirements.txt`. From the repository root:

```powershell
python -m research.anchor_handover.predict --input path\to\features.json
python -m unittest research.anchor_handover.tests.test_inference -v
python -m unittest discover -s research\tests -v
python -m unittest research.anchor_v3.tests.test_v3 -v
```

The v2 and v3 implementation/artifacts are preserved. No frontend or backend
application files are part of this package.
